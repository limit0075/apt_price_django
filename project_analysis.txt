1. 프로젝트 개요
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  아파트 실거래가 데이터를 조회·시각화하는 단일 포트 웹 애플리케이션.
  공공데이터포털(실거래가), EPOST(주소), KAPT(세대/주차), 카카오(지도),
  네이버(블로그) 등 5개 외부 API를 연동하여 DB 없이 실시간으로 데이터를
  수집·가공·제공한다.

  [원본 → Django 이식 경위]
  - 원본: Jupyter 노트북 기반 CLI 스크립트 (fetch_data11.py, query_apts 함수)
  - 이식: FastAPI 버전을 거쳐 최종적으로 Django 단일 서버로 통합
  - 핵심 데이터 로직(fetch_data11.py)은 그대로 유지하고,
    services.py → api.py 레이어를 덧씌워 웹 API 형태로 제공

3. 연동 외부 API 목록
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [1] 공공데이터포털 — 아파트 실거래가
      - 키: DATAGO_KEY (.env)
      - 라이브러리: datakart.Datagokr
      - 사용: datago.lawd_code(시도명), datago.apt_trade(법정동코드, YYYYMM)
      - 특징: 월별 API 호출 → concat → DataFrame 반환
              개인 거래(buyerGbn == '개인')만 필터링

  [2] EPOST 도로명주소 API
      - 키: POSTAL_KEY (.env)
      - URL: openapi.epost.go.kr/postal/retrieveNewAdressAreaCdService/...
      - 사용: 도로명/지번/우편번호 → 주소 후보 검색
      - 특징: lru_cache(maxsize=50000) 로 중복 호출 방지
              searchSe 파라미터: "road"(도로명) / "dong"(지번) / "post"(우편번호)

  [3] KAPT (공동주택관리정보시스템)
      - 키: KAPT_KEY (.env)
      - URL: apis.data.go.kr/1613000/...
      - 사용 API:
          · getSidoAptList3    — 시도별 단지 전체 목록 (lru_cache(2000))
          · getAphusBassInfoV4 — 단지 기본정보(세대수 등) (lru_cache(50000))
          · getAphusDtlInfoV4  — 단지 상세정보(주차대수) (lru_cache(50000))
      - 특징: 다단계 점수 기반 자동 매칭 (주소점수 + 이름유사도 + 숫자겹침)

  [4] 카카오 로컬 API
      - 키: KAKAO_REST_KEY (.env)
      - URL: dapi.kakao.com/v2/local/...
      - 사용: 주소 지오코딩(→ lat/lng), 카테고리 주변검색
              카테고리: 학교(SC4), 마트(MT1), 병원(HP8), 지하철(SW8)

  [5] 네이버 블로그 검색 API
      - 키: NAVER_CLIENT_ID, NAVER_CLIENT_SECRET (.env)
      - URL: openapi.naver.com/v1/search/blog.json
      - 사용: 단지명 + "임장" 키워드로 블로그 포스트 검색
              '임장' 키워드 포함 결과만 최대 5개 반환

  [요청 처리 흐름]

  HTTP 요청
    └─► api.py (View Layer)
         ├─ JSON 파싱 (_body)
         ├─ 필수 파라미터 검증 (_require_base)
         ├─ ThreadPoolExecutor로 블로킹 작업 실행 (_run)
         └─► services.py (Service Layer)
               ├─ 비즈니스 로직 조합
               ├─ 데이터 정규화 (만원→원 변환, 날짜 정규화 등)
               ├─ 시 전체 캐시 관리 (get_city_area_price)
               └─► fetch_data11.py (Data Layer)
                     ├─ area_sort()         — 법정동코드 조회
                     ├─ area_price()        — 실거래 데이터 수집 (datakart)
                     ├─ epost_search_top()  — 주소 검색 (EPOST API)
                     ├─ kapt_list_by_sido() — KAPT 단지 목록
                     ├─ get_kapt_basic_raw()       — 세대수 등
                     ├─ get_kapt_detail_parking()  — 주차 정보
                     └─ enrich_house_parking_by_choice() — KAPT 자동확정

  ┌─ api.py 주요 특징 ───────────────────────────────────────────────────────┐
  │  · @csrf_exempt: 모든 POST API에 CSRF 면제                               │
  │  · ThreadPoolExecutor(max_workers=4): 동기 Django에서 블로킹 I/O 처리    │
  │  · _SafeEncoder: pandas NA/NaT/Timestamp, numpy int/float → JSON 직렬화  │
  └─────────────────────────────────────────────────────────────────────────┘

  ┌─ services.py 주요 특징 ─────────────────────────────────────────────────┐
  │  · _city_cache: 시 전체 실거래 데이터 인메모리 캐시 (threading.Lock)     │
  │  · parse_money_to_manwon(): "8억 5000" → 85000 (만원 단위)               │
  │  · normalize_price_to_won(): 만원 → 원 (프론트엔드 기준)                 │
  │  · build_price_series(): 월별 평균가 시계열 생성                         │
  │  · build_district_compare_series(): 구 전체 면적별 평균가                │
  │  · build_district_bars(): 시 전체 구별 평균가 (비교용)                   │
  │  · compute_district_stats(): 구내 백분위 계산                            │
  └─────────────────────────────────────────────────────────────────────────┘

  ┌─ fetch_data11.py 주요 특징 ─────────────────────────────────────────────┐
  │  · merge_complex_name(): "(고층)/(저층)" 표기 제거 → 동일 단지 병합      │
  │  · choose_kapt_auto_strict(): 다단계 점수로 KAPT 단지 자동 확정          │
  │    점수 = 주소점수(zip+10, 도로명×6, 지번×4, 동번지+6)                   │
  │          + 이름유사도×6 + 숫자겹침×3.5 + 세대수(tie-break)               │
  │  · lru_cache 적극 활용: epost_search_top(50000), kapt_list(2000),        │
  │    get_kapt_basic_raw(50000), get_kapt_detail_parking(50000)              │

  │    실거래 집계 → 가격필터 → KAPT 매칭 → 세대수필터 → 병합명 기준 집계   │
  └─────────────────────────────────────────────────────────────────────────┘

7. 주소 검색 모드 — 상세 흐름
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Step 1. 주소 입력 및 후보 검색
  ───────────────────────────────
  사용자가 도로명 / 지번 / 우편번호 중 하나 입력
  → _detect_addr_mode()로 입력 유형 판별 (road / jibun / zip)
  → epost_search_top(searchSe, 검색어, top_n=10) 호출
  → 후보 목록 반환 (zipNo, roadAddress, jibunAddress)

  Step 2. 단지 목록 조회
  ───────────────────────
  사용자가 주소 후보 클릭
  → area_price(City, District, start_date, end_date)로 해당 기간 실거래 수집
  → narrow_base_by_selected_address():
      1차: 법정동 + 번지 직접 매칭
      2차 fallback: 우편번호 기반 매칭 (add_road_zip_columns → EPOST 역조회)
  → 필터링된 DataFrame에서 단지명(aptNm) unique 목록 추출 → 반환

  → fill_representative_address_from_rows(): EPOST로 대표 도로명/우편번호 확정
  → chosen_from_representative_address(): 동·번지 파싱
  → enrich_house_parking_by_choice(): KAPT 자동 매칭 → 세대수/주차 컬럼 추가
  → normalize_result_items(): 모든 행을 표준 dict로 변환
  → build_price_series(): 월별 평균가 시계열
  → build_compare_series(): 면적별 평균가
  → build_district_compare_series(): 구 전체 면적별 평균가
  → build_district_bars(): 시 전체 구별 평균가 (city_cache 활용)
  → compute_district_stats(): 현재 단지의 구내 백분위
  → 최종 JSON 응답 반환

  [별도 비동기] nearby API 호출

10. 핵심 알고리즘 및 설계 결정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [1] 단지명 병합 (merge_complex_name)
  ────────────────────────────────────
  공공데이터에서 동일 단지가 "상계주공10(고층)", "상계주공10(저층)"으로
  분리 수록되는 문제를 regex로 "(고층)/(저층)" 제거 후 병합.
  → 두 레코드를 하나의 단지로 통합하여 세대수·거래건수 집계 정확도 향상

  [2] KAPT 자동 확정 알고리즘 (choose_kapt_auto_strict)
  ──────────────────────────────────────────────────────
  실거래 데이터의 단지명을 KAPT 단지코드와 매핑하기 위한 다단계 점수:

    최종점수 = 주소점수 + 이름유사도점수 + 숫자겹침점수 + 세대수(tie-break)

    · 주소점수 (addr_sc):
        우편번호 일치: +10점
        도로명 유사도 × 6점
        지번 유사도 × 4점
        동+번지 포함 여부: +6점

    · 이름유사도점수 (name_sc):
        SequenceMatcher ratio × 6점 (가중치)

    · 숫자겹침점수 (digit_sc):
        단지번호(숫자)가 일치할수록 높은 점수 × 3.5점

    → 항상 1위 후보를 자동 확정 (사용자 입력 없음)
    → 점수가 낮아도 확정하되 WARN 로그 출력

  [3] 주소 매칭 2단계 fallback (narrow_base_by_selected_address)
  ──────────────────────────────────────────────────────────────
    1차: 법정동(동명) + 번지 직접 비교 (가장 정확)
    2차: EPOST API로 각 거래 행의 법정동+본번+부번 → 우편번호 역조회 후
         선택 우편번호와 비교 (느리지만 fallback으로 유효)

  [4] 시 전체 실거래 캐시 (_city_cache)
  ────────────────────────────────────
  구별 비교 차트를 위해 서울특별시 전체(25개 구) 실거래를 수집해야 함.
  처음 요청 시 25개 구를 ThreadPoolExecutor(max_workers=5)로 병렬 수집 후
  인메모리 딕셔너리에 (City, start_date, end_date) 키로 캐싱.
  이후 동일 조건 요청은 캐시에서 즉시 반환.

  [5] 동기 Django에서 블로킹 I/O 처리
  ─────────────────────────────────────
  Django는 기본적으로 동기(sync) 방식이므로, 외부 API 호출(수십 초 소요)이
  메인 스레드를 점유하면 다른 요청 처리 불가.
  → api.py의 _executor(ThreadPoolExecutor, max_workers=4)를 통해
    블로킹 작업을 별도 스레드에서 실행 후 future.result(timeout=120)로 대기

  [6] pandas/numpy JSON 직렬화 (_SafeEncoder)
  ────────────────────────────────────────────
  pandas NA, NaT, Timestamp, numpy int64/float64/ndarray 등은
  기본 JSONEncoder가 처리 불가 → _SafeEncoder 커스텀 인코더로 해결
  (api.address_results, filter_list 등에서 encoder=_SafeEncoder 지정)

14. 성능 최적화 포인트 및 한계
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [최적화]
  · lru_cache: EPOST/KAPT API 중복 호출 차단 (메모리 내 캐싱)
  · 시 전체 캐시: 구별 비교 차트용 데이터를 최초 1회만 수집
  · ThreadPoolExecutor: 실거래 월별 데이터 수집, 지오코딩 병렬화
  · KAPT 단지 목록: 시도 단위로 한 번에 수집 후 로컬 필터링

  [한계 / 주의사항]
  · 인메모리 캐시 → 서버 재시작 시 초기화
  · lru_cache → 프로세스 단위 (멀티 프로세스 배포 시 공유 안 됨)
  · API 호출 속도 제한: 실거래 API는 요청 간 0.18초 sleep 적용
  · 시 전체 수집(구별 비교)은 최초 요청 시 수십 초 소요
  · KAPT 자동 확정 점수가 낮으면 잘못된 단지 매칭 가능 (WARN 로그)
  · 네이버 블로그: '임장' 키워드 포함 여부로만 필터링 (정밀도 제한)
